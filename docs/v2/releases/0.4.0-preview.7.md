# Groundwork v2 0.4.0-preview.7

This patch preview preserves declared index order for counted relational pages.
All 26 public packages and `Groundwork.Tool` use the exact immutable version
`0.4.0-preview.7` and are published only to the Valence Works Groundwork Feedz
source.

## Release identity and compatibility

The production source for this release is the merge of PR #384 to `main`,
commit `fce747b57b637461e372206ed8b991571ccceeb3`. The release-preparation
commit changes only release metadata, documentation, and install/version pins;
it does not change `src/`, `samples/`, or `benchmarks/`. Package repository
metadata on every artifact identifies the tagged release commit.

All 26 package identities in `eng/public-packages.txt` remain one versioned
closure and must be upgraded together. This release changes relational query
execution shape only. The public query API, result semantics, diagnostic
inventory, and persisted catalog contract are unchanged. Existing
`0.4.0-preview.6` catalogs remain compatible: no catalog discard, migration,
schema re-application, or data rewrite is required. Do not mix preview.6 and
preview.7 packages in one process.

## Counted relational pages

For a relational `ResultShape.TotalCount` query with a page, SQLite, PostgreSQL,
and SQL Server now execute the ordered page and its filtered total count as two
statements in one provider command and round trip. The page statement applies
the declared effective order and paging; the count statement counts the full
filtered source. This removes the previous outer count/page envelope, whose
final ordering could force a temporary sort even when the bounded page itself
was served by the selected index.

The materializer attaches the count to the page result and retains it when the
page is empty without exposing its internal count-only marker. Rows retain
their exact effective order and continuation behavior, and `TotalCount`
continues to describe the full filtered source. Distinct, latest-per-key,
joined, keyset, offset, null-ordering, and projection semantics continue to be
applied provider-side. The existing unpaged distinct count-only optimization
remains a single count result.

Explain assertion mode inspects every statement in a counted command and
requires the declared index in each plan while treating them as one logical
command. The two statements reuse one parameter set and execute inside the
caller's existing transaction when one is present. Its isolation level governs
whether concurrent commits can become visible between the page and count
statements; `TotalCount` does not promise snapshot isolation in a
read-committed session.

## Native AOT sample verification

The package-only Native AOT verifier now starts its explicit one-time schema
bootstrap in the Development host environment, as required by startup admission,
then returns to Production with runtime auto-apply disabled for the repeatable
startup and HTTP proof. The run-from-source documentation names the same
Development environment explicitly.

## Projected distinct identities

Columns-only distinct pages now use the complete projected tuple as their
deterministic paging identity instead of appending the physical source-row
identity. Relational renderers may stream a native `SELECT DISTINCT` shape
when every projected string is paired with an explicitly declared injective
ordinal key; other text shapes retain the exact ranked form that preserves
portable equality across providers. `QuerySearchKeyColumn` exposes the explicit
`PreservesOrdinalIdentity` opt-in for this execution shape.

This is an execution-shape and public query-contract addition only. It does not
change existing distinct results or require a persisted catalog migration.

restore the complete closure from the Valence Works Groundwork Feedz source.
