# Groundwork v2 0.4.0-preview.7

This patch preview keeps counted relational pages on their declared index order.
All public packages and `Groundwork.Tool` remain one exact-version closure and
must be upgraded together.

## Counted relational pages

SQLite, PostgreSQL, and SQL Server now return an ordered page and its filtered
total count as two result sets in one database command and one provider round
trip. This removes the previous outer count/page envelope, whose final ordering
could force a temporary sort even when the bounded page itself was served by
the selected index.

The public result remains unchanged: rows retain exact effective order and
continuation behavior, `TotalCount` describes the full filtered source, and an
empty page still carries its total count without exposing an internal sentinel.
Distinct, latest-per-key, joined, keyset, offset, null-ordering, and projection
semantics continue to be applied provider-side. Explain assertion mode inspects
and requires the declared index in both statements while treating them as one
logical command.

The two statements execute inside the caller's existing transaction when one is
present. Its isolation level determines whether concurrent commits can become
visible between the page and count statements; `TotalCount` does not add a
snapshot-isolation guarantee to a read-committed session.

This is a provider execution-shape change only. It adds no public API,
diagnostic code, or persisted-schema change, and existing applied catalogs need
no schema action.

## Upgrade

Pin every Groundwork package and `Groundwork.Tool` to `0.4.0-preview.7` and
restore the complete closure from the Valence Works Groundwork Feedz source.
