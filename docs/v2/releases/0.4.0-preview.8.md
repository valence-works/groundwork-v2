# Groundwork v2 0.4.0-preview.8

This patch preview preserves declared index order for counted relational pages,
adds schema-authoritative ordinal identity projections for projected distinct
pages, and retargets exact equality predicates to those persisted identities.
All 26 public packages and `Groundwork.Tool` use the exact immutable
version `0.4.0-preview.8` and are published only to the Valence Works
Groundwork Feedz source.

## Release identity and compatibility

The production source for this release is the merge of PR #389 to `main`.
Package repository metadata on every artifact identifies the tagged release
commit.

All 26 package identities remain one versioned closure and must be upgraded
together. This release changes relational query execution shape and adds an
opt-in persisted projection. Existing `0.4.0-preview.7` catalogs remain
compatible when the new declaration is not used. Do not mix preview.7 and
preview.8 packages in one process.

## Counted relational pages

For a relational `ResultShape.TotalCount` query with a page, SQLite, PostgreSQL,
and SQL Server execute the ordered page and its filtered total count as two
statements in one provider command and round trip. The page statement applies
the declared effective order and paging; the count statement counts the full
filtered source. This removes the previous outer count/page envelope, whose
final ordering could force a temporary sort even when the bounded page itself
was served by the selected index.

The materializer attaches the count to the page result and retains it when the
page is empty without exposing its internal count-only marker. Rows retain their
exact effective order and continuation behavior, and `TotalCount` continues to
describe the full filtered source. Distinct, latest-per-key, joined, keyset,
offset, null-ordering, and projection semantics continue to be applied
provider-side.

## Projected distinct identities

Columns-only distinct pages use the complete projected tuple as their
deterministic paging identity instead of appending the physical source-row
identity. Relational renderers may stream a native `SELECT DISTINCT` shape when
every projected string is paired with an explicitly declared injective ordinal
key; other text shapes retain the exact ranked form that preserves portable
equality across providers. The projected tie-break extension is limited to
portable ordinal strings and the exact portable decimal shape `(18,4)`.

Declare an ordinal identity with `ColumnBuilder.OrdinalIdentity` when a string
needs that execution shape. Groundwork expands the declaration into a
provider-owned, persisted text column, backfills it during schema apply, and
derives it as `PortableStringComparison.CreateOrdinal(source)` on every write.
Callers cannot supply or override the physical identity value. Mark a dedicated
index with `IndexBuilder.UseOrdinalIdentities` to retarget its identity column
and retain the logical source as a covering column. Unmarked composite indexes
remain logical, avoiding hidden-key width costs; normal table projection fetches
the source whenever a covering index is not selected. Exact non-null equality
predicates on an ordinal-identity source use the same physical identity only when
the selected index contains it, while null equality remains on the logical source
to preserve null semantics. Existing distinct results remain unchanged; opting into the
declaration is an additive schema change applied through the normal catalog
migration path. Adding the marker to an existing named index changes that
index's canonical fingerprint and requires an explicitly authorized rebuild;
deployment tooling reports the exact rebuild operation rather than silently
changing the catalog.

`IndexDefinition.IncludedColumns` carries explicit covering-column metadata in
physical schema snapshots. SQL Server and PostgreSQL emit native `INCLUDE`
columns; SQLite and MySQL/MariaDB lower them to trailing key columns because
those engines have no native include clause. Portable validation rejects
undeclared, duplicate, or key-overlapping includes, and rejects arbitrary
includes on unique indexes where fallback lowering could change uniqueness.
Malformed included-column references report `GW-DECL-INDEX-004`, `-005`, or
`-006`.
