# Groundwork v2 0.4.0-preview.29

Release notes for the pull requests merged after `0.4.0-preview.28`. The
canonical release run identifier and merge commit are recorded when the
release is published.

## MongoDB `_id` point reads collect their plan (#423 follow-up)

A MongoDB point read's plan was requested since `0.4.0-preview.28` but came back
`Unsupported`: the server answers an `_id` lookup with its fast path (classic
`IDHACK`, which names no index, or the 8.0 express scan naming `_id_`), and the
mapper knew neither stage. Both now map to one `PrimaryKeySearch` of the target
with no index identity, the same node SQLite's rowid lookup and SQL Server's
primary-key seek report. An `IDHACK` stage that names an index or carries an
input stage, and an express scan that names no index, still withhold the forest;
an express scan of another index is an `IndexSearch`.

## PostgreSQL row-value continuation without a nominated index (#422 follow-up)

PostgreSQL's native row-value tuple continuation required a nominated index,
so a consumer that stopped nominating (an ordinal identity orders through its
persisted key since `0.4.0-preview.27`) fell back to the lexicographic
disjunction, and for some cursors the planner answered that `OR` with a
bitmap-or and a sort instead of the index scan, withholding the page's plan.
The tuple path now takes the first declared index that exposes the ordered
segment when none is selected; the eligibility rules (non-null, index-typed,
uniformly directed terms, ordinal identities through their persisted key) are
unchanged. Elsa observed this on `elsa-workflows/elsa-foundation#1618`.
