# Groundwork v2 0.2.0-preview.1

This release is a clean-break preview schema boundary. All public packages in
the release use the exact version `0.2.0-preview.1` and are published only to
the Valence Works Groundwork Feedz source.

## Required SQLite catalog reset

`Groundwork.Sqlite` now stores portable ordinal strings with the registered
`GROUNDWORK_UTF16_ORDINAL` collation. Ordinary indexes inherit that same
collation, so equality/range predicates and index ordering use the required
.NET UTF-16 ordinal semantics—including supplementary characters—and native
plans can use the declared indexes.

SQLite catalogs created by an earlier v2 preview physically declare those
columns as `BINARY`. They are not compatible with this corrected persisted
schema contract. Delete and recreate every such preview catalog, then apply
the current storage declarations before writing data. There is deliberately
no migration, alias, dual-write, fallback, or compatibility mode.

PostgreSQL, SQL Server, and MongoDB declarations do not require a physical
catalog reset for this specific correction. Applications should nevertheless
move their complete Groundwork v2 package closure to the exact release version
rather than mixing preview package versions.

## Other changes

- Runtime-composed aggregations can now use the existing closed grouping and reducer vocabulary
  under an explicit `AggregationAcceptance` carrying an inventory id, reason, owner, expiry,
  `MaxGroups`, and `MaxInputRows`. Missing or expired acceptances fail before provider I/O;
  scoped and privileged-access rules remain unchanged. Accepted-aggregation metadata must be
  statically inventoryable; unresolved values fail closed with `GW-AGG-ADHOC-906`.
- `Groundwork.Store` exposes `StorageUnit.CreateQueryRenderOptions`, allowing
  consumers to derive query index metadata from the admitted declaration.
  Optional index selection remains provider-default evidence and never becomes
  an optimizer hint.
- Relational query results report an expected provider-default index separately
  from whether a native hint was applied.
- MongoDB transactional same-identity races return portable deterministic write
  outcomes; wrapper-owned transactions retry transient write-conflict bodies.
- `IStorageSession.UpdateWhere`/`DeleteWhere` add admitted set-based mutation
  across all four providers. The extensions apply the same coverage gate as a
  read, refuse unsupported providers and invalid assignments with `GW-SET-001`
  through `GW-SET-004`, preserve provider-owned folded search keys, flush staged
  unit-of-work writes before the native statement, and report one portable
  aggregate `MatchedRows` count. Runtime admission now also requires declared
  indexes to be present in the deployed catalog, applies the provider's value
  fence, and excludes locale-only sort-key indexes from mutation coverage;
  unsupported unit-of-work wrappers do not advertise set mutation or flush
  staged rows on refusal. Updates increment optimistic tokens; these operations
  do not use the append idempotency ledger, so callers must resolve unknown
  acknowledgements before retrying when token stability matters. Exact per-row
  mutation outcomes remain a separately tracked follow-up.
- The in-memory reference provider now applies the same kernel-planned schema
  evolution as shipped providers. An authorized physical key-column rename is
  matched by stable logical ID and preserves stored rows; key identity changes,
  reordering, and incompatible type changes remain refused.
- The provider-neutral query model and closed LINQ surface now carry mapped projections, `Distinct`,
  and deterministic `First`/`FirstOrDefault` plus over-one-detecting `Single`/`SingleOrDefault`
  cardinality shapes. Distinct
  projections are coverage-checked against candidate indexes, and new order diagnostics are
  recorded as `GW-SEM-ORDER-006` and `GW-LINQ-111`. Because Distinct is materialized after the
  provider read, an unbounded distinct projection requires an equality/range predicate or an
  explicit accepted scan; a bounded `Take` alone does not make that read covered.
- The provider-neutral query model and closed LINQ surface now carry `Sum`, `Min`, and `Max`
  terminals over one mapped covered column. `Sum` accepts only `Int32`/`Int64`/`Decimal` and
  returns nullable `Int64`/`Decimal`; closed `Min`/`Max` overloads accept the supported orderable
  types. Every reduction ignores nulls and returns null when no non-null input exists. Offset-only
  `Skip` pages fail closed as `GW-LINQ-113`, and reductions after `Select` fail closed in both the
  runtime and analyzer. Reduction targets participate in index coverage and use `GW-LINQ-112`,
  `GW-SEM-AGG-001`, and `GW-SEM-AGG-002` for non-portable selectors. Provider rendering and
  four-way differential evidence are tracked by #150.
- SQLite no longer risks pooling a connection whose rollback failed while its
  native transaction stayed open. Microsoft.Data.Sqlite marks a transaction
  "completed" in a `finally` block regardless of whether the ROLLBACK it issues
  succeeds, so a rollback that fails under contention still let a poisoned
  connection return to the pool looking clean; the next caller to draw it saw
  "cannot start a transaction within a transaction" or a refused PRAGMA for
  unrelated work. `SqliteUnitOfWork` and `SqliteStorageSession`'s single-write
  path now share one guard that clears the connection-string pool group when a
  rollback fails, discarding that connection instead of recirculating it. The
  standalone session path also closes and retires its checked-out connection
  and becomes unusable, so it cannot issue another write against a stranded
  native transaction. For shared in-memory sessions, the provider is retired
  as a whole so sibling sessions cannot use a closed shared connection. The
  pool clear also tears down every idle connection
  sharing that connection string in-process, and
  marks every other checked-out one non-poolable, as the price of a failure
  path that is otherwise rare.
- `IStorageSession.BatchRead`/`BatchReadAsync` add a keyed batch-read primitive
  that chunks unbounded key sets under provider-owned parameter and payload
  budgets, preserving the injected scope parameter for relational sessions and
  staying conservatively below MongoDB's BSON command-size ceiling. When no
  connection is supplied, the shared planner applies a 15 MiB payload fence;
  an explicit admission profile can advertise a different deployment budget.
  Results are merged in caller key order and report unmatched representatives
  through `MissingKeys`; folded string equivalents use the persisted search key,
  occur once, retain the first requested spelling, and refuse a mismatched
  `ColumnRef` policy with `GW-QUERY-031`. Invalid table, key, or provider result
  contracts refuse with `GW-BATCHREAD-001` through `GW-BATCHREAD-003`; an
  individual key that cannot fit refuses with `GW-BATCHREAD-004`. MongoDB now
  advertises its lack of a bound-parameter ceiling explicitly, while ordinary
  membership retains the renderer's portable 1,000-value limit.
- Live SQL Server and MongoDB test databases now carry server-clocked owner
  leases. The owning process refreshes its heartbeat for its lifetime, and a
  later acquire can reclaim only an expired lease it atomically fences; missing
  or malformed metadata is preserved. SQL Server also serializes database
  creation and markerless reclamation by generated name, and reclaims an
  interrupted unmarked acquisition only after the server-side creation age
  crosses the same two-hour window.

## Release evidence

The release requires the full four-provider CI suite, the explicit 22-package
allowlist, package layout verification, the package-only public API journey,
and a post-publication clean restore of every package from Feedz.
