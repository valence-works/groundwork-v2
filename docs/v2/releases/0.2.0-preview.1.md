# Groundwork v2 0.2.0-preview.1

This release is a clean-break preview schema boundary. All public packages in
the release use the exact version `0.2.0-preview.1` and are published only to
the Valence Works Groundwork Feedz source.

## Required SQLite catalog reset

`Groundwork.Sqlite` now stores portable ordinal strings with the registered
`GROUNDWORK_UTF16_ORDINAL` collation. Ordinary indexes inherit that same
collation, so equality/range predicates and index ordering use the required
.NET UTF-16 ordinal semantics—including supplementary characters—and native
plans can use the declared indexes.

SQLite catalogs created by an earlier v2 preview physically declare those
columns as `BINARY`. They are not compatible with this corrected persisted
schema contract. Delete and recreate every such preview catalog, then apply
the current storage declarations before writing data. There is deliberately
no migration, alias, dual-write, fallback, or compatibility mode.

PostgreSQL, SQL Server, and MongoDB declarations do not require a physical
catalog reset for this specific correction. Applications should nevertheless
move their complete Groundwork v2 package closure to the exact release version
rather than mixing preview package versions.

## SQL Server effective parameter budget

`Groundwork.SqlServer` now advertises and enforces **2,098 caller-owned bind
parameters** per command. SQL Server's 2,100 statement limit reserves two
parameters for the `Microsoft.Data.SqlClient` `sp_executesql` wrapper, so
queries that previously relied on 2,099 or 2,100 application parameters now
refuse with `GW-QUERY-015` before provider I/O. Applications that reach this
boundary should split the membership or page it into smaller requests. Keyed
batch reads retain their existing 2,098-key budget; the driver overhead is not
subtracted a second time.

## Other changes

- `Groundwork.Query.Model` now represents one same-scope inner equi-join through a named declared
  reference. `ReferenceJoin` carries the ordered source-to-target-key equality pairs, and joined
  requests require every `ColumnRef` to be qualified as either the source or target table; unqualified
  element-set predicates remain refused until they gain a side identity. Join identity participates
  in shape and continuation fingerprints; the query-shape encoding is
  intentionally versioned from `q2` to `q3`, invalidating preview-era recognized-shape inventories
  and continuation tokens compiled under `q2`. This is the model boundary only; typed navigation,
  declaration/scope admission and both-sides coverage (`#165`), provider rendering (`#168`/`#169`),
  and composite materialization (`#170`) land in the following relationship slices. Until those
  renderers land, direct execution of the new node fails
  closed before provider I/O with `GW-QUERY-032` rather than silently running only the driving table.
- Joined keyset continuations now use one canonical composite identity order: requested terms,
  qualified driving-key tie-breaks, then the declared target key in reference order. Continuation
  ordering and provider-page projection metadata keep same-named columns on opposite sides distinct;
  typed composite row materialization follows in `#170`. Bound token encoding validates every value
  against its tuple position. The token continues to bind the query shape and anonymous scope or
  privileged-access discriminator, so it cannot be replayed under another invocation or a changed
  reference mapping.
- Storage declarations can now name logical-only references from ordered source columns to another
  unit's key. The kernel builder, Records compatibility builder, and canonical schema model carry
  the metadata without creating physical foreign keys. `GW-DECL-REF-001` through
  `GW-DECL-REF-005` refuse invalid source columns, target-key shape, scope policy, portable types,
  and missing covering keys/indexes before provider I/O. Canonical documents and persisted applied
  state omit an empty reference collection, preserving existing document fingerprints and history
  rows. Non-empty references now participate in the schema-subject fingerprint, while declaration
  order remains irrelevant. Schema-tool target reports expose references as logical metadata rather
  than physical operations, and unresolved or mismatched cross-unit targets surface as per-target
  plan refusals; apply and adopt preflight stop before any provider mutation.
- `IStorageProviderConnection.Schema` now exposes the kernel runtime schema-admission result,
  including safe-plan authorization when startup auto-apply is enabled. Hosting delegates its
  startup verdict to that provider seam instead of reclassifying `SchemaDiff` changes, keeping
  startup, provider runtime, and kernel admission on one rule. Successful safe auto-apply now
  reports the post-application `Ready` verdict and does not retain stale index-drift refusals.
- MongoDB's native schema coordinator now reads and publishes the same kernel applied-schema ledger
  as the deployment tool. `Schema.Apply` therefore carries logical-id renames through the shared
  physical plan and application path. The applied history row is now the runtime's sole durable
  declaration authority; the legacy `schema:<id>` catalog cache cannot make a session open after
  an interrupted publication or supply search-key algorithm evidence during adoption. The same
  per-target history document now carries the application fence, making publication one atomic
  compare-and-set on replica sets and standalone servers alike. Stable Mongo declarations are
  guarded inside the lease-verified apply path and report `GW-PORT-008` for key-order changes and
  `GW-MONGO-001` through `GW-MONGO-003` for the remaining stable metadata conflicts. The obsolete
  Mongo-only `GW-SCHEMA-009` diagnostic is removed.
- `PhysicalSchemaDiffPlan.PreviousDefinition` exposes the immutable declaration a plan was derived
  against, so provider change descriptions can include declaration-only changes without a second
  unlocked history read.
- Portability validation now refuses a declared default whose CLR runtime type does not match
  its column's `PortableType`, using `GW-PORT-013` with the column, declared type, and supplied
  type in the diagnostic. This generalizes the existing `Double` default guard across the
  portable type set, while JSON retains its intentional multi-shape scalar/object/array graph,
  and keeps provider-specific coercion out of declaration deployment.
- Runtime-composed aggregations can now use the existing closed grouping and reducer vocabulary
  under an explicit `AggregationAcceptance` carrying an inventory id, reason, owner, expiry,
  `MaxGroups`, and `MaxInputRows`. Missing or expired acceptances fail before provider I/O;
  scoped and privileged-access rules remain unchanged. Accepted-aggregation metadata must be
  statically inventoryable; unresolved values fail closed with `GW-AGG-ADHOC-906`.
- Typed Records callers can bind declared aggregation profiles to group-key and reducer-result
  selectors with `RecordTable<T>.Aggregate`; aliases and CLR result types are checked before
  execution, and the Records.Store adapter forwards the binding to the existing covered
  aggregation runtime without exposing ad-hoc shapes.
- `Groundwork.Store` exposes `StorageUnit.CreateQueryRenderOptions`, allowing
  consumers to derive query index metadata from the admitted declaration.
  Optional index selection remains provider-default evidence and never becomes
  an optimizer hint.
- Relational query results report an expected provider-default index separately
  from whether a native hint was applied.
- MongoDB transactional same-identity races return portable deterministic write
  outcomes; wrapper-owned transactions retry transient write-conflict bodies.
- `IStorageSession.UpdateWhere`/`DeleteWhere` add admitted set-based mutation
  across all four providers. The extensions apply the same coverage gate as a
  read, refuse unsupported providers and invalid assignments with `GW-SET-001`
  through `GW-SET-004`, preserve provider-owned folded search keys, flush staged
  unit-of-work writes before the native statement, and report one portable
  aggregate `MatchedRows` count. Runtime admission now also requires declared
  indexes to be present in the deployed catalog, applies the provider's value
  fence, and excludes locale-only sort-key indexes from mutation coverage;
  unsupported unit-of-work wrappers do not advertise set mutation or flush
  staged rows on refusal. Updates increment optimistic tokens; these operations
  do not use the append idempotency ledger, so callers must resolve unknown
  acknowledgements before retrying when token stability matters. Aggregate mode
  remains the default affected-count path.
- Set-based mutations now accept `SetMutationOptions.Exact`, returning one keyed
  `WriteOutcome` per selected row in deterministic key order. Exact mode uses the
  existing keyed mutation contract so optimistic versions and not-found/conflict
  statuses remain portable; a mutation invoked through a unit-of-work session
  flushes earlier staged writes before taking its key snapshot, and later staged
  keyed writes run after the set operation. An interrupted or failed exact
  mutation poisons its unit of work, so the normal commit failure path rolls back
  any keyed writes already applied instead of making a partial set durable. Exact
  mode does not use the append idempotency ledger; callers should resolve unknown
  acknowledgements before retrying.
- The in-memory reference provider now applies the same kernel-planned schema
  evolution as shipped providers. An authorized physical key-column rename is
  matched by stable logical ID and preserves stored rows; key identity changes,
  reordering, and incompatible type changes remain refused.
- `Schema.Apply` now enforces the same declaration-reference rules as the fluent
  builder before provider physicalization or schema I/O. Directly constructed
  units with a missing, undeclared, or duplicate key/index column—or a JSON
  index column—are refused with the existing `GW-DECL-KEY-*` and
  `GW-DECL-INDEX-*` diagnostics instead of bypassing the builder-only guard.
  `ProviderOwnedColumns.ValidateLogicalDeclaration` now performs these reference
  checks as well as its existing provider-owned-name check; compound-invalid
  declarations report the portable `GW-DECL-*` reference refusal first.
- The provider-neutral query model and closed LINQ surface now carry mapped projections, `Distinct`,
  and deterministic `First`/`FirstOrDefault` plus over-one-detecting `Single`/`SingleOrDefault`
  cardinality shapes. Distinct
  projections are coverage-checked against candidate indexes, and new order diagnostics are
  recorded as `GW-SEM-ORDER-006` and `GW-LINQ-111`. Because native Distinct must de-duplicate the
  projected values at the provider, an unbounded distinct projection requires an equality/range
  predicate or an explicit accepted scan; a bounded `Take` alone does not make that read covered.
- The provider-neutral query model and closed LINQ surface now carry `Sum`, `Min`, and `Max`
  terminals over one mapped covered column. `Sum` accepts only `Int32`/`Int64`/`Decimal` and
  returns nullable `Int64`/`Decimal`; closed `Min`/`Max` overloads accept the supported orderable
  types. Every reduction ignores nulls and returns null when no non-null input exists. Offset-only
  `Skip` pages fail closed as `GW-LINQ-113`, and reductions after `Select` fail closed in both the
  runtime and analyzer. Reduction targets participate in index coverage and use `GW-LINQ-112`,
  `GW-SEM-AGG-001`, and `GW-SEM-AGG-002` for non-portable selectors. Async `SumAsync`, `MinAsync`,
  and `MaxAsync` now dispatch through a safe scalar executor seam; all four providers render these
  reductions natively, applying distinct and input paging before aggregation without client-side
  row fallback. Nulls are ignored, no-non-null input returns null, and integer sums are nullable
  `Int64`.
- External implementations of `Groundwork.Query.Linq.IGwQueryExecutor` must implement the new
  abstract `ReduceAsync<TResult>(QueryRequest, CancellationToken)` method. The
  `Groundwork.Query.Linq` contract now requires that method to dispatch reductions to a
  provider-native scalar execution path; adapters that only support row materialization must add
  this method before upgrading.
- SQLite no longer risks pooling a connection whose rollback failed while its
  native transaction stayed open. Microsoft.Data.Sqlite marks a transaction
  "completed" in a `finally` block regardless of whether the ROLLBACK it issues
  succeeds, so a rollback that fails under contention still let a poisoned
  connection return to the pool looking clean; the next caller to draw it saw
  "cannot start a transaction within a transaction" or a refused PRAGMA for
  unrelated work. `SqliteUnitOfWork` and `SqliteStorageSession`'s single-write
  path now share one guard that clears the connection-string pool group when a
  rollback fails, discarding that connection instead of recirculating it. The
  standalone session path also closes and retires its checked-out connection
  and becomes unusable, so it cannot issue another write against a stranded
  native transaction. For shared in-memory sessions, the provider is retired
  as a whole so sibling sessions cannot use a closed shared connection. The
  pool clear also tears down every idle connection
  sharing that connection string in-process, and
  marks every other checked-out one non-poolable, as the price of a failure
  path that is otherwise rare.
- `IStorageProviderConnection.OpenOwnedSession` now provides a deterministic per-caller session
  lifetime across all providers. Owned relational sessions use independent connections and return
  them on synchronous or asynchronous disposal; MongoDB and in-memory sessions enforce the same
  release/use-after-dispose contract. The dependency-injection `IGroundworkStorage` opens and
  releases owned sessions with each scope, so request-scoped access does not retain one provider
  handle per request.
- This is a deliberate source-contract change for third-party providers: implementations of
  `IStorageProviderConnection` must add `OpenOwnedSession`. Implementations of `IGroundworkStorage`
  must also implement `IAsyncDisposable`, and `IOwnedStorageSession` implementations must report
  their idempotent release state through `IsReleased`; existing legacy `OpenSession` and unit-of-work
  sessions remain non-owning and do not implement `IOwnedStorageSession`.
- Relational batch fallbacks now reuse their active batch transaction without reacquiring the
  non-reentrant shared-session gate. Independent callers remain serialized on shared sessions,
  while owned sessions bypass that gate because their connections are independent. This addresses
  #207's captured 23-hour PostgreSQL dump (PID 25945): `ApplyBatchAsync -> ExecuteWrite` held the
  connection `SemaphoreSlim` while `ApplyBatchFallback -> ConditionalUpsertAsync -> Execute`
  attempted to reacquire it; the regression now completes the same fallback under a bounded timeout.
- `IStorageSession.BatchRead`/`BatchReadAsync` add a keyed batch-read primitive
  that chunks unbounded key sets under provider-owned parameter and payload
  budgets, preserving the injected scope parameter for relational sessions and
  staying conservatively below MongoDB's BSON command-size ceiling. When no
  connection is supplied, the shared planner applies a 15 MiB payload fence;
  an explicit admission profile can advertise a different deployment budget.
  Results are merged in caller key order and report unmatched representatives
  through `MissingKeys`; folded string equivalents use the persisted search key,
  occur once, retain the first requested spelling, and refuse a mismatched
  `ColumnRef` policy with `GW-QUERY-031`. Invalid table, key, or provider result
  contracts refuse with `GW-BATCHREAD-001` through `GW-BATCHREAD-003`; an
  individual key that cannot fit refuses with `GW-BATCHREAD-004`. MongoDB now
  advertises its lack of a bound-parameter ceiling explicitly, while ordinary
  membership retains the renderer's portable 1,000-value limit.
- Live SQL Server and MongoDB test databases now carry server-clocked owner
  leases. The owning process refreshes its heartbeat for its lifetime, and a
  later acquire can reclaim only an expired lease it atomically fences; missing
  or malformed metadata is preserved. SQL Server also serializes database
  creation and markerless reclamation by generated name, and reclaims an
  interrupted unmarked acquisition only after the server-side creation age
  crosses the same two-hour window.

## Nonportable coverage refusals do not suggest an index

`GW-COVER-016` means the query shape itself cannot be represented by a portable
ordered index. Provider-default null ordering, ordering a Boolean, Double, or
Binary column, a nonportable range, a cross-column `Or`, and other predicates
that are not representable by an ordered index now omit the `Add: [GwIndex(...)]`
line from their refusal message. Declaring another index could not clear those
refusals; rewrite the query into a portable shape where possible, or mark the
read with `.AcceptScan(...)`. An otherwise actionable `GW-COVER-005` remains
unchanged and includes its index suggestion when no `GW-COVER-016` refusal is
also present.
