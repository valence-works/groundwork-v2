## Withheld plans say why (ADR 0004)

`ProviderPlanEvidence.WithheldReason` names the structural reason a provider
withheld a requested native plan: `NotAttempted`, `MultipleStatements`,
`TransactionScope`, `NoCatalogWitness`, `AmbiguousIndexNames`, `NoSinglePlan`,
`UnmappedNativeShape` or `UnmappedColumns`. Every value is a fact about the
collection attempt, never a query value, and it is present only on
`Unsupported` evidence. Until now a consumer whose admission rule required a
collected plan could tell only that a page was withheld, not whether the
explain replay produced no plan, the catalog returned no witness, two
declarations shared a physical index name, or the mapper met a native shape it
does not close over; Elsa's hosted SQL Server lane spent four probe runs on that
question (elsa-workflows/elsa-foundation#1618).

## SQL Server parallel plans are exchanges, not unknown shapes (#448 follow-up)

On a multi-core server SQL Server answers a large lookup join with a parallel
plan: `Top → Parallelism (Gather Streams) → Nested Loops(Filter → Index Seek,
RID Lookup)`. The mapper knew no `Parallelism` operator and withheld the whole
forest, so Elsa's hosted SQL Server lane (four cores) rejected a keyset page
that its emulated single-writer container had always answered serially.
`ProviderPlanOperator.Exchange` names a native parallelism exchange (gather,
distribute or repartition streams): one input, no target, and, for an ordered
gather, the keys it merges on as native sort keys. A `Parallelism` node with
more than one input still withholds the forest.
