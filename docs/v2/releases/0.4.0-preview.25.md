## SQL Server plan evidence admits the bookmark lookup of an index seek (#448)

A non-covering index seek on SQL Server fetches the remaining columns through a
`RID Lookup` (heap) or `Key Lookup` (clustered table) joined to the seek by a
`Nested Loops`. `SqlServerNativePlanMapper` used to withhold the whole forest
for any join, so the plan evidence for such a seek was `Unsupported` although
the seek was on the expected index. The mapper now maps that one join shape:
the join and the lookup become `Materialize` nodes without a target, the fact
MongoDB's `FETCH` stage reports, and the seek stays the forest's single access
node. Genuine multi-source joins still withhold the forest.
