## SQL Server sort keys report the ordinal string key as one term (#445)

SQL Server renders an ordinal string ordering term as the binary-collated column
followed by `DATALENGTH(column)`, and its optimizer drops the trailing length key
once a unique column precedes it. `SqlServerNativePlanMapper` now folds the
adjacent pair into one `OrdinalStringKey` sort key with an `Ordinal` comparison,
reports the collated column alone as a plain key whose comparison is `Ordinal`,
and marks a key on an ordinal identity mapping's physical column with
`PhysicalSearchKey`, so a sort node's native keys line up term for term with the
bounded query's ordering evidence the way the PostgreSQL and MongoDB mappers
already do.
