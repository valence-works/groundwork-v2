# Groundwork v2 0.4.0-preview.10

This preview lets MongoDB execute selected non-null ordering indexes without
provider-generated sort expressions, while retaining portable ordering for
nullable and ordinary string columns.

## MongoDB index-covering order

MongoDB queries whose selected index declares an order column non-null no
longer add a computed null-rank field for that term. When an ordered logical
string has been retargeted to a persisted `OrderByPhysicalColumn` search-key
or ordinal-identity projection, MongoDB also sorts the physical key directly
instead of computing a JavaScript ordinal key. This allows the optimizer to
select the declared compound index for the complete filter and order without
an index hint. Keyset continuation predicates use the same persisted key
directly, so later pages retain the index-backed plan instead of falling back
to a JavaScript comparison expression.

Only physical keys declared with `PreservesOrdinalIdentity` may replace a
logical identity tie-break. Non-injective locale sort keys retain the logical
column after the physical order key so continuation cannot skip colliding
values.

Nullable order terms keep their explicit null-rank expression, and ordinary
string columns keep the portable ordinal-key expression. Continuation tokens
and public projections are unchanged; provider-owned ordering fields remain
execution details.
