# Groundwork v2 0.4.0-preview.18

This preview narrows the SQLite provider gate so that file-backed sessions are no
longer queued behind an unrelated caller's unit of work.

## SQLite provider gate scope

`0.4.0-preview.9` serialized every SQLite session open and every non-unit-of-work
session command on one provider gate and held that gate for the complete
lifetime of a unit of work. A host that commits background batches in units of
work on the same provider connection its request path uses therefore paid the
whole batch lifetime on every request-path session open and command; Elsa
Foundation measured its HTTP p95 doubling on adoption
(valence-works/groundwork-v2#424).

The gate now covers only what shares state: units of work against each other,
schema and catalog work, provider disposal, and commands on a shared in-memory
connection. A session on a file-backed store opens and runs on its own
connection while another caller's unit of work is active. Its reads proceed
under WAL; its writes wait on SQLite's own writer lock through the connection's
busy timeout instead of on the provider gate. Concurrent callers sharing one
session view are serialized on a per-session gate, as the PostgreSQL and SQL
Server views already were. The transferable unit-of-work lease, its terminal
release, the observer re-entry refusals, and deferred provider cleanup while a
unit of work is open are unchanged. A unit of work can no longer be begun from
inside a command observer callback on any thread; that refusal previously
applied only when the callback ran on the gate-holding thread.

Provider disposal now takes a registry lock around session registration, so a
session that is registering while `Dispose` starts is still closed by that
disposal rather than missed.
