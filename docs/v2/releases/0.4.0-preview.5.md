# Groundwork v2 0.4.0-preview.5

This patch preview completes provider-neutral Unicode ordinal ignore-case
substring matching over string-array elements. All public packages and
`Groundwork.Tool` use the exact immutable version `0.4.0-preview.5` and are
published only to the Valence Works Groundwork Feedz source.

## Persisted positional element search keys

A JSON string-array column can now declare `ElementSearchKey` with
`UnicodeOrdinalIgnoreCase`. Groundwork maintains a provider-owned positional JSON
array containing the versioned boundary search key for each valid string element;
null and non-string members retain their slot as JSON null. Queries are rewritten
to this physical form only when the declaration and algorithm identity match.
Missing, mismatched, or stale mappings fail closed.

An optional positive `MaximumElementCodeUnits` bound is part of the derived
algorithm identity. Writes and schema backfills refuse over-bound or ill-formed
UTF-16 elements rather than truncating them. Changing the bound plans an
authorized validation backfill before the revised declaration is admitted.

SQLite JSON1, PostgreSQL JSONB, SQL Server `OPENJSON`, MySQL/MariaDB
`JSON_TABLE`, and MongoDB expressions evaluate the predicate on the server.
InMemory remains the semantic oracle. Adjacent elements are never concatenated,
and malformed, missing, null, mixed-member, or empty owners fail closed.

All current element-substring forms remain bounded-scan-only. `GW-COVER-016`
continues to require explicit accepted-scan evidence; declaring the positional key
does not create or imply an index-admissible plan. `GW-PORT-016` reports invalid
element search-key declarations.

## Compatibility and schema application

Existing catalogs that do not declare an element search key remain byte-stable
and compatible. Opting a column into `ElementSearchKey` changes that storage
unit's schema identity and requires an explicit schema apply to add and backfill
the parallel key array before Unicode element-substring queries are admitted.

SQL Server query parameters longer than 4,000 UTF-16 code units are now bound as
`nvarchar(max)`, preventing long suffix-search needles from being truncated by inferred
parameter metadata. A `Contains` needle longer than the native 8,000-code-unit
`CHARINDEX` limit resolves to match-none when it exceeds the declaration's enforced
`MaximumElementCodeUnits`; without such a bound, SQL Server refuses the request before
provider I/O rather than truncating it. Other providers retain their existing binding behavior.

All package identities in `eng/public-packages.txt` remain one versioned closure
and must be upgraded together. Do not mix `0.4.0-preview.4` and
`0.4.0-preview.5` packages in one process.

## Upgrade

Pin every Groundwork package and the tool to `0.4.0-preview.5`, restore the
complete closure from the Feedz source, review the schema plan for declarations
that add `ElementSearchKey`, and deploy with the explicit safe apply path.
