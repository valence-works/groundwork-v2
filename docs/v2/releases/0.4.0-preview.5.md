# Groundwork v2 0.4.0-preview.5

This preview delivers bounded affected-key evidence, safer hosted schema
startup, an independently deployable schema tool, and provider-neutral Unicode
substring matching over string-array elements. All public packages and
`Groundwork.Tool` use the exact immutable version `0.4.0-preview.5` and are
published only to the Valence Works Groundwork Feedz source.

## Release identity and compatibility

The production source for this release is the merge of PR #376 to `main`,
commit `bc0ff312ad47d0964de674c72879dedfa647d0e1`. The release-preparation
commit changes only release metadata, documentation, and install/version pins;
it does not change `src/`, `samples/`, or `benchmarks/`. Package repository
metadata on every artifact identifies the tagged release commit.

All 26 package identities in `eng/public-packages.txt` remain one versioned
closure and must be upgraded together. This release adds public contracts and
diagnostics while preserving existing preview.4 catalogs. A catalog changes
identity only when a JSON column opts into the new `ElementSearchKey`
declaration; review and apply that explicit schema plan before issuing Unicode
element-substring queries. No catalog discard is required.

## Bounded affected-key retention evidence

Exact retention can now request an optional bounded affected-key projection
through `RetentionAffectedKeyProjection`,
`RetentionOperationResult.AffectedKeys`, and
`IExactRetentionAffectedKeysStorageSession`. InMemory, SQLite, PostgreSQL, SQL
Server, and transaction-capable MongoDB enforce native `bound + 1` refusal,
canonical replay/conflict semantics, and atomic ledger/row mutation.
Standalone MongoDB omits the capability.

The public bound is capped at 1,000,000 values. Binary projections require a
positive declared `MaxLength` of at most 16 MiB, keeping every admitted result
replayable by the durable codec. Count-only requests retain their preview.4
fingerprint and replay format.

## Persisted positional element search keys

`Predicate.ElementSubstring` adds provider-neutral `Contains` and `EndsWith`
matching against each member of a typed string array. Raw arrays admit ordinal
and exact ASCII A-Z ignore-case comparison. Empty needles match every string
member, duplicate members do not affect the result, adjacent members are never
joined, and null, missing, malformed, mixed-member, or empty owners fail
closed.

A JSON string-array column can declare `ElementSearchKey` with
`UnicodeOrdinalIgnoreCase`. Groundwork maintains a provider-owned positional
JSON array containing the versioned boundary search key for each string
element; null and non-string members retain their slot as JSON null. Queries
use this physical form only when the declaration and algorithm identity match.
Missing, mismatched, or stale mappings fail closed.

An optional positive `MaximumElementCodeUnits` bound is part of the derived
algorithm identity. Writes and schema backfills refuse over-bound or
ill-formed UTF-16 elements rather than truncating them. Changing the bound
plans an authorized validation backfill before the revised declaration is
admitted.

SQLite JSON1, PostgreSQL JSONB, SQL Server `OPENJSON`, MySQL/MariaDB
`JSON_TABLE`, and MongoDB expressions evaluate the predicate on the server.
InMemory remains the semantic oracle.

All current element-substring forms remain bounded-scan-only.
`GW-COVER-016` requires explicit accepted-scan evidence; declaring the
positional key does not imply an index-admissible plan. `GW-PORT-016` reports
invalid element search-key declarations.

SQL Server query parameters longer than 4,000 UTF-16 code units are bound as
`nvarchar(max)`. A `Contains` needle beyond the native 8,000-code-unit
`CHARINDEX` limit resolves to match-none when it exceeds the declaration's
enforced element bound; without such a bound, SQL Server refuses before
provider I/O rather than truncating the request. Negated element-substring
forms retain the portable `GW-SEM-NOT-001` refusal.

## Hosted schema application safety

`Groundwork.Extensions.DependencyInjection` now refuses startup when a named
connection enables `AutoApplyOnStartup` outside the Development environment.
`GW-HOST-007` is raised before startup admission can mutate schema and directs
operators to review `groundwork plan` and use `groundwork apply --safe` in the
deployment step. Development hosts retain the explicit safe-plan auto-apply
option and warning.

A directly constructed environment-less `GroundworkAdmissionRunner` remains
inspect-only because it has no trusted host-environment context.

## Independently deployable schema tool

`Groundwork.Tool` now embeds the first-party SQLite, PostgreSQL, SQL Server,
MongoDB, and MySQL schema provider plug-ins and their required assets. A fresh
tool installation can use those provider aliases without an application build
or custom host. Third-party providers continue to use
`--provider-assembly <file>`.

Subcommand help is available, and execution failures include concise inner
exception detail in `GW-CLI-010` after connection-secret redaction. An isolated
deployment step can now run:

```bash
groundwork apply --schema groundwork.schema.json \
  --provider sqlite --database ./app.db --safe
```

## Operations and distribution

The documented local MongoDB replica-set fixture now provisions
`--ulimit nofile=64000:64000`, avoiding the Docker 1,024-descriptor default
that can terminate WiredTiger during the live-provider matrix. Existing
containers must be recreated because a restart cannot change their configured
limit.

Feedz-only GitHub prereleases no longer trigger the nuget.org workflow.
`publish-nuget.yml` is manual-only and retains exact-version confirmation,
package, clean-room, integrity, credential, symbol, protected-environment, and
post-publication restore gates. Publishing this GitHub release starts only the
Feedz package workflow.

## Upgrade

Pin every Groundwork package and the tool to `0.4.0-preview.5`, restore the
complete closure from the Feedz source, review any declaration that adds
`ElementSearchKey`, and apply schema through the explicit safe deployment
path. Do not mix preview.4 and preview.5 packages in one process.
