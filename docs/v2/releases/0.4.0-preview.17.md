# Groundwork v2 0.4.0-preview.17

Unreleased candidate notes for #405. Publication and four-provider acceptance
are still pending; this document is not a release announcement.

## Structured execution evidence

The additive `IProviderExecutionObserver` capability reports value-free terminal
execution evidence through the existing command-observer registration. It
separates actual command outcomes, emitted semantic shapes and independently
requested native-plan evidence. Legacy command callbacks retain their counting
semantics; native plan collection is separately accounted diagnostic work.

Opaque capture-local identities correlate commands, statements, physical targets
and indexes without exposing scope-bearing physical names. Missing or unsupported
facts do not imply successful acceptance. Native plan structure preserves
operators and parentage, including a Limit operator whose presence alone does not
establish a numeric bound. A fused `TopNSort` node retains both sorting and
row-limiting semantics without splitting one native operator into invented nodes.
PostgreSQL plan evidence also rejects malformed index conditions and child
layouts instead of presenting them as complete access-path evidence.
Generic aggregate and function-source operators preserve nested native work,
including the computation used by PostgreSQL ordinal-string ordering. Such
nodes do not imply a second storage target or observed execution statistics.
Generic compute, projection and offset operators likewise retain native row
transformations without exposing expressions or inferring bounds from their
presence.

SQL Server's initial native-plan mapping uses same-command `STATISTICS XML`
replay and a same-connection catalog witness. It distinguishes supported index
seeks/scans, table scans, scalar computations, sorts and limits, preserving their native parentage.
Unknown operators or incomplete trees withhold the plan rather than producing
partial acceptance evidence. Catalog lookup, enabling statistics, replay and
cleanup are counted separately from legacy observed application commands.
Cleanup is non-cancellable; a failed cleanup retires the session connection.
This candidate's live SQL Server acceptance remains a separate pending gate.

See the [consumer migration guide](../structured-execution-evidence.md) and
[ADR 0004](../../adr/0004-structured-provider-execution-evidence.md) for provenance,
redaction, persistence and provider coverage boundaries. The runtime types are
not a default JSON wire format; durable consumers must retain the actual
callback through a versioned artifact mapping and validate it after reload.

## MongoDB first-document reads

MongoDB's structured shape capture is emitted alongside the native renderer,
with terminal outcome callbacks and capture-local identities. Unsupported
predicate or ordering shapes are withheld as a whole. Evidence ownership uses
weak references and is allocated only for structured observers, so a long-lived
provider connection does not retain every opened session.

The MongoDB native-plan mapper recognizes supported classic and slot-based
winning-plan envelopes, with an exact target-namespace witness. It preserves
supported cursor access operators and aggregate compute, projection, sort,
offset and limit stages. Execution-stat metadata is validated separately from
operators and does not become a claim about the original command's execution.
Malformed, foreign-target or unsupported structures withhold the entire forest.
Opt-in collection replays the actual command with `executionStats` and reports
`ExplainReplay` provenance with one separately counted diagnostic command.
Structured index choice is derived only from the mapped winning forest, never
from a rejected plan or an unsupported mapping. A plan-only failure does not
change the recorded successful application-read outcome, but its original
exception propagates after terminal observation, consistently with the relational
providers. Observer failures cannot mask that pending exception. Requested point-read
plans remain explicitly unsupported. Live MongoDB acceptance remains pending
in this candidate.

The execution helper retains the driver's fluent find type when selecting the
first document. Both synchronous and asynchronous find terminals therefore
apply a native limit of one, rather than only selecting one document from a
cursor without that limit. This aligns point-read command descriptions with
the driver operation while preserving the returned result and legacy callbacks.

## Point-read cancellation boundary

Relational point-read evidence is emitted only after the driver call is reached.
Cancellation between the legacy pre-execution callback and that call no longer
claims an issued command. SQLite's async point-read path also retains the caller's
token through native execution instead of checking it only at method entry.

## Upgrade gate

Do not adopt this candidate as a published release until package publication
and exact-feed restore have been verified. Local proof packages are development
artifacts, not the final consumer dependency.
