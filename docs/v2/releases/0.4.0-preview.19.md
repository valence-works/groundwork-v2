# Groundwork v2 0.4.0-preview.19

Candidate notes for valence-works/groundwork-v2#421. This preview extends the typed
native-plan evidence published in preview.17 with observed sort, bound and spill
details, so consumers can retire the last provider-plan parsers that
preview.17's operator-only forest left in place.

## Native plan node details

`ProviderPlanNode` gains optional `ProviderPlanNodeDetails` on sort, top-N sort
and limit nodes: `NativeSortKeys` as logical `ProviderOrderTerm`s, `NativeLimit`
as an `Unknown`/`Absent`/`Explicit` bound, and `Spill` as an observed spill
fact with provider-reported metrics. Every value is tri-state; a missing value is
"not observed", never a claim of no sort, no bound or no spill. The kernel
refuses a spill fact on estimated-explain provenance and refuses details on
nodes that cannot carry them. `ProviderPlanForest.ObservedRootOrder` records
the observed order of sibling native roots without asserting parentage.

Per provider:

- PostgreSQL (estimated `EXPLAIN VERBOSE`): sort keys mapped from `Sort Key`
  terms through the query's identity-preserving search-key mappings, with
  direction and null placement. No native bound is exposed, and `Plan Rows` is
  never used as one. No spill fact.
- SQL Server (same-command `STATISTICS XML` replay): `OrderBy` columns mapped
  to logical columns, `datalength(column)` recognised as the `OrdinalStringKey`
  transform, literal `TopSort` row counts and `Top` constants as explicit
  bounds, and a spill observation from `SpillToTempDb` warnings or their absence
  under runtime information.
- MongoDB (`executionStats` replay): `$sort`/`SORT` keys, fused and standalone
  literal limits, `usedDisk` with spilled record and storage metrics, and the
  observed pipeline stage order.
- SQLite: unchanged; `EXPLAIN QUERY PLAN` exposes sort purpose only.

Keys that name a foreign relation, an unresolvable expression, or a
provider-owned column without a recorded mapping leave the key set unobserved
rather than partially mapped. Values, raw expressions and physical scope names
are not exported.
