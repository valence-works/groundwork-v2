## Ordinal identities order through their persisted key without a nomination (#443)

`SearchKeyQueryMappings` exposed a column's persisted ordinal identity key only
when the query's *selected* index contained it; a query that nominated no index
ordered and compared the logical column, so the renderer computed the ordinal
key at execution time and no declared index could serve the sort. When no index
is selected, the mapping now uses the persisted key whenever any declared index
that uses ordinal identities contains it, so the provider's optimizer can serve
the identity's equality and order from that index. A selected ordinary route
still keeps the logical column, which is what its index covers.
