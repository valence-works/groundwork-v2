# Groundwork v2 0.4.0-preview.9

This preview removes the obsolete `StorageAccessValidation.ObservePrivilegedQuery`
helper, makes MongoDB point-read observer descriptions structured and safely
redacted, and serializes SQLite unit-of-work lifetimes.

## MongoDB point-read observer descriptions

The single non-probe `mongodb.read` event raised by a MongoDB point read now
uses stable JSON describing the resolved physical collection, an `_id`
equality filter with a redacted identity, and `limit: 1`. The description has
no ordering clause. Composite identities retain their shape while every
identity value is redacted. Scoped collection names remain provider-derived;
caller keys, storage-scope plaintext, credentials, and connection details are
not included.

## SQLite unit-of-work serialization

SQLite now serializes provider session, schema, and catalog setup through one
provider gate, and holds that gate for the complete lifetime of a unit of work.
The lease is released after commit, rollback, disposal, or a failed unit-of-work
creation, so concurrent callers wait for a terminal outcome instead of entering
SQLite's native writer lock independently. Disposing the provider while a unit
of work is active no longer waits on that same lease; handle cleanup finishes
when the transaction reaches a terminal path.

SQLite catalog reads now use a fresh native handle. This prevents an older
pooled handle from hiding an index applied after that handle was opened, which
could otherwise make an index-covered read or set mutation fail admission.

## Removed obsolete privileged-query helper

`Groundwork.Store` no longer exports `StorageAccessValidation.ObservePrivilegedQuery`.
The one-shot helper has been obsolete since `0.2.0-preview.1` and cannot satisfy the
privileged-query attempt/success/failure lifecycle. Provider authors must call
`StorageAccessValidation.BeginPrivilegedQuery` and complete the returned
`StorageAccessAuditOperation` with `Success` or `Failure`. In-tree providers already
do this. Existing catalogs and diagnostic codes are unchanged.

## Concurrency evidence

The provider-backed W2 harness now opens one owned session for each independent
writer and releases it when that writer finishes. This exercises the concurrent
caller contract instead of serializing the workload through legacy non-owning
sessions. SQL Server's eight W2 matrix shapes are also reported as separate test
cases, so a stalled shape is identified directly and the per-test hang collector
does not mistake progress across the complete matrix for one inactive test.
